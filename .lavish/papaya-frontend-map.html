papaya-frontend-monorepo · main

Four surfaces, one set of tokens.

The monorepo ships three products — a React web app, an Astro marketing site, and native iOS/macOS clients — plus a non-shipping design workspace. There's no workspace tool; a root Makefile stitches them together, and the shared ground between web, marketing, and native is a single tokens file.

The Makefile: the only glue

There is no root package.json, turbo, or nx. The root Makefile is the whole orchestration layer — 39 targets, each ##-annotated for make help, grouped by surface. Ports are parameterised (FRONTEND_PORT 5173, MARKETING_PORT 5175) so worktrees don't collide, and frontend-worktree-env generates a per-worktree port file.

The web app: URL → panel

Every product route renders one component, AppPage, which maps the path onto a PanelType union. The URL is the only view state, so filters and open records are deep-linkable.

Key components

API client

frontend/src/lib/api.ts
  • Base URL, auth headers + token refresh
  • Typed ApiError / apiErrorDetail
  • Timezone injection boundary

UI kit

frontend/src/components/ui-kit/
  • shadcn "new-york" style: Radix + CVA + lucide
  • blocks/ — metric grids, charts, timelines, decision cards, provenance
  • activity/, streaming/, documents/ sub-kits

State

frontend/src/store/
  • auth (persisted) · chat (channels, threads, agent streams, panels)
  • documents · billing · connections · subscriptions

Data fetching

frontend/src/lib/panelData.ts
  • No React Query — homegrown stale-while-revalidate usePanelData
  • Module cache per workspace, cleared on logout

Realtime & streaming

hooks/useWebSocket.ts · lib/agentStream*.ts
  • One socket per workspace, backoff reconnect
  • Polling fallbacks for agent turns and block streams
  • Vercel AI SDK + streamdown; consent/write-action cards

Wire types

frontend/src/types/index.ts
  • ~2,000-line contract shared by every panel
  • PanelType / DetailPanelType unions
  • blocks, agentTurns, billing types alongside

Native client

ios-v2/Papaya · ios-v2/PapayaMac
  • View folders mirror the web domain 1:1
  • Networking: API, auth/keychain, socket, turn poller, agent client
  • ~21 MVVM view models, WorkspaceStore

Marketing site

marketing/src/pages · components/sections
  • Home, product, pricing, business, integrations, manifesto, legal, writing/
  • Animated React vignettes (chat, dashboard)
  • Owns the estate's only apex→www redirect

Quality & delivery

Makefile · .github/workflows

  • CI builds web + marketing images; deploy hands off to papaya-infra → Cloud Run
